# NUSA Verify

NUSA Verify is a static student identity verification site for NUSA — AME Zion Chapter. Public verification uses a narrowly scoped Supabase RPC; authenticated administrators manage student records through Supabase Auth and row-level security.

## Project files

- `index.html`, `login.html`, `dashboard.html`, `verify.html`: public home, administrator sign-in, protected dashboard shell, and public verification.
- `css/style.css`: responsive visual system.
- `js/`: Supabase configuration/client, auth, dashboard, QR, verification, and PWA registration.
- `supabase/setup.sql`: database schema, RLS, authorization, and public verification RPC.
- `.github/workflows/deploy.yml`: GitHub Pages deployment.
- `manifest.json`, `sw.js`: subpath-safe PWA shell. No private data or API responses are cached.
- `assets/logo.png`: reserved for the official organization logo; no unofficial emblem is included.

## Supabase setup

1. Create a Supabase project and open its SQL Editor.
2. Run `supabase/setup.sql` in full. It can be safely rerun to update policies and functions.
3. In Supabase Authentication settings, add the GitHub Pages website URL to **Site URL** and **Redirect URLs** after Pages is deployed. Keep public sign-up disabled; create administrator accounts through the Supabase dashboard.
4. In `js/config.js`, set `SUPABASE_URL` to the project URL and `SUPABASE_ANON_KEY` to the project's publishable/anon key. These are intended for browser use. Never put a service-role or secret key in this repository.
5. Create the first administrator in Supabase Authentication, then run the following in the SQL Editor with that account's exact email:

   ```sql
   insert into public.admin_users (user_id)
   select id from auth.users where email = 'admin@example.org'
   on conflict (user_id) do nothing;
   ```

   Repeat this step for any additional administrator. Only listed user IDs can manage student records.

The SQL does not insert a sample student or expose student rows to anonymous clients. An admin can create the requested `NUSA-TEST-001` test record from the dashboard.

## Configure and deploy

The GitHub repository is `nmarzah8-sudo/NUSA-VERIFY-SYSTEM-`, whose expected GitHub Pages project URL is `https://nmarzah8-sudo.github.io/NUSA-VERIFY-SYSTEM-/`. GitHub Pages must be enabled with **Build and deployment: GitHub Actions** in repository Settings before the workflow can publish. Push to `main` or manually run **Deploy NUSA Verify** in the Actions tab.

`PUBLIC_BASE_URL` in `js/config.js` is an optional override for a production HTTPS origin/base path, for example `https://nmarzah8-sudo.github.io/NUSA-VERIFY-SYSTEM-/`. When it is blank, the app derives the correct base path only while running on a `*.github.io` host. It deliberately does not generate QR links on localhost, Codespaces, or other preview hosts. Set an explicit HTTPS base URL if using a custom domain. The final deployed URL must be confirmed in the Pages settings/Actions deployment output.

## SQL sections

The executable SQL is kept in one file so policies, grants, table constraints, and RPC behavior remain versioned together:

1. Extensions and tables (`students`, `admin_users`).
2. Updated timestamp trigger and `is_admin()` authorization function.
3. RLS policies and least-privilege table/function grants.
4. `verify_student(lookup_token uuid)`, which returns only full name, student ID, major, current position, and current status.

Student ID is the primary key (no generic record ID). The unique UUID verification token is generated by PostgreSQL, remains unchanged during ordinary edits, and is never included in the public RPC response. To rotate a token intentionally, an administrator can update it in the database; the previous QR then stops resolving.

## Verification behavior

The QR contains only the absolute `verify.html?token=<uuid>` URL. The public page calls `verify_student`; it never queries the students table. Active, Inactive, Graduated, and Revoked records are all clearly labeled, and no token/record is cached by the service worker.

The app can be checked locally as static files, but local preview QR generation is intentionally disabled. Public reachability, QR scanning from a separate device, real Supabase login, and database operations can only be confirmed after Supabase configuration and a successful GitHub Pages deployment.
